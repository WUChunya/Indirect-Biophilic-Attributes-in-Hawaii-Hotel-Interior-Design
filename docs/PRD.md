## §1 背景：2024 年论文做了什么

论文 *Indirect Biophilic Attributes in Hawaii Hotel Interior Design — A Comparative Study of Waikiki Four-Star Hotels*（夏威夷大学，2024）。核心想法：**不去现场，只用网上的照片、评分和评论，就能把室内的"间接亲自然设计"（Kellert 的 indirect experience of nature）和酒店的线上表现联系起来，甚至做预测。**

| 章节 | 做法 | 数据 |
|---|---|---|
| Ch3 BDIA 量表 | 三轮专家评审，把 Kellert 的属性收敛成 7 类 29 条二元（有/无）指标，在客房 / 大堂 / Lounge 三个场景分别打分 | 第 3 轮：20 位设计专业人员，6 家酒店，Kappa 0.79 |
| Ch4.1–4.2 指数与预测 | 26 家威基基四星酒店，每家 3 位评审只看照片盲评，取众数；随机森林算权重，29 条删到 16 条，得出 BDIA-Index 和 "Booking 分 = 7.292 + 1.854 × BDIA-Index"（R² 0.488） | `data/raw/bdia_coding_36_hotels.xlsx` |
| Ch4.3 NLP | Booking.com 评论关键词 + 情感词计数 | `data/raw/reviews_booking_waikiki_2020-2023.xlsx`，`legacy/` |
| Ch5 问卷 | S-O-R 模型，115 份有效问卷，看 6 家酒店的照片，SEM 路径分析 | `data/raw/survey_instrument_and_results.xlsx`（只有结果，没有原始回答） |
| Ch6 外部检验 | 另抽 10 家：5 家夏威夷其它岛四星 + 5 家低星级，用同一公式检验 | 同上 coding 文件的 27–36 号 |
| Ch7 手册 | 每类 BDIA 的推荐等级和案例 | `docs/papers/Indirect_Biophilic_Design_Handbook_EDRA55_2024.pdf` |

## §2 审计结论（详细证据：`docs/LEGACY_AUDIT.md`，数字：`results/REPORT.md`）

**站得住的：**
1. BDIA 量表本身和盲评流程（只看照片、3 人取众数）是好的设计，数据可以继续用。
2. 用一个**完全不看结果变量**的简单指数（7 个维度各占一份、三个空间等权），在 26 家威基基模型酒店里，BDIA 和 Booking 总分依然明显正相关：Spearman ρ = 0.65（95% CI 0.31–0.86），留一酒店预测 R² = 0.39，控制价格后仍在；和随机森林权重的 0.67 几乎一样。也就是说，**核心发现用更简单、更干净的方法依然成立，权重没有带来任何东西**。36 家合并、控制价格和星级 / 地区后，指数系数仍为正（REPORT §4）。
3. 评论层面（同一家酒店内部比较，酒店固定效应）：夸自然光/阳台/通风 +0.59 分、夸"夏威夷本地风格" +0.70、夸复古/历史感 +0.32（1–10 分制）；抱怨陈旧 −0.94（REPORT §6）。
4. 照片和评论能对上的一处：照片里"时间感/复古"（F 维度）越多的酒店，客人越常提到复古、历史感（ρ ≈ 0.6，FDR 后显著；REPORT §7）。

**需要降低的说法：** 26 家酒店里，**29 条单项在 FDR 校正后没有一条显著**（论文做法下"显著"的有 10 条）。所以手册里"哪一条最重要、该多用哪一条"的逐条推荐目前没有统计支持，只能在维度层面谈（G 自然几何、C 自然色彩最强）。外部检验里，指数会系统性高估低星级酒店约 0.8 分——星级必须作为控制变量。

**站不住、必须改的：**
1. **循环论证（target leakage）**：权重 = 用 Booking 总分训练的随机森林重要性；29→16 的删减、三个空间的权重也是按同一个总分挑的；然后再拿这个指数去"预测"同一个总分。R² 0.488 因此不能作为证据。
2. **随机行切分泄漏**：26 家 × 3 个空间 = 78 行，同一家酒店的 3 行目标值相同，随机 90/10 切分让测试酒店的另外两行留在训练集里。论文报告的测试 R² 0.732 来自一次切分；论文自己的表 19 里简化 16 项模型的测试 R² 是 **−1.116**（比直接猜平均值还差），正文却写"训练和测试结果匹配"。按酒店整家留出时，随机森林基本没有预测力（REPORT §3）。
3. **伪重复（pseudo-replication）**：相关和回归在 78 / 108 / 156 行上做，实际独立单位只有 26（或 36）家酒店，p 值被严重低估（D-W = 0.623 就是信号）；29 条 × 5 个分数也没做多重比较校正。
4. **公式前后不一致**：电子表格里实际用的是 29 条权重（G01 = 0.231）、`0.368×大堂 + 0.285×客房 + 0.347×Lounge`、`7.304 + 1.911×指数`；手册 / 论文写的是 16 条、`0.368×客房 + 0.285×Lounge + 0.347×大堂`、`7.292 + 1.854×指数`。
5. **NLP 部分**：代码不完整、跑不起来；"35,000 条评论"里 45% 是 Booking 的占位句 "There are no comments available for this review"，真正有文字的约 1.96 万条；关键词大量误判（"a stone's throw" 算石材、"looked like the photos" 算自然图像、"closed for painting" 算画作、"Polynesian Hostel" 算本地文化）；没有否定处理、没有分母、一条评论按情感词数量重复计数。
6. **问卷 SEM**：BDIA-Index 是酒店层面的变量，只有 6 个不同取值，却按 115 个独立样本估计路径；手册写"高 BDIA 直接提高'夏威夷感'"，但 SEM 表里 BDIA → Nature Attachment 的 p = 0.346（不显著）。

**一个实质性的新发现：** 客人在评论里**很少直接说**间接亲自然元素。高精度词命中："自然形态"1 次、"自然几何"1 次、"自然色彩"4 次、"自然材料"约 30 次（REPORT §6）。所以**评论不能用来测量 BDIA**，只能用来测量"客人注意到了什么、对什么满意"。BDIA 的测量必须靠照片。

## §3 研究问题与假设（重新设计）

| ID | 问题 | 分析单位 | 主要检验（事先确定） |
|---|---|---|---|
| RQ1 测量 | BDIA 能否从照片可靠编码？视觉大模型（VLM）能否复现专家盲评？ | 酒店 × 空间 × 条目 | 每条的 Gwet AC1 和 Cohen κ（VLM vs 2024 专家众数）。H1：中位数 AC1 ≥ 0.60。 |
| RQ2 关联 | 不看结果变量定义的 BDIA 指数，与 Booking 总分及空间相关子分（设施、舒适）是否相关？控制价格和星级后还在吗？ | 酒店 | 26 家模型酒店：Spearman + bootstrap CI + 置换检验；OLS（HC3）+ 留一法预测 R²；36 家：加星级 / 地区虚拟变量。H2：ρ > 0，95% CI 不含 0。 |
| RQ3 感知 | 同一家酒店内，评论里夸/抱怨某类设计的客人，评分是否不同？客人到底注意哪些设计？ | 评论（酒店固定效应） | OLS + 酒店固定效应 + 按酒店聚类 SE。H3：自然光与空气、本地风格、复古/时间感的正面提及系数 > 0。 |
| RQ4 一致性 | 照片里 BDIA 多的酒店，客人是否更常提到、更正面地评价对应元素？ | 酒店 | 维度分数 vs 提及率 / 净情感，Spearman + FDR。 |
| RQ5 外部检验 | 在 26 家上建立的关系，能否推到 10 家测试酒店？ | 酒店 | 训练 26 → 预测 10 的 R²、MAE；分组残差（低星级组是否系统偏差）。 |
| RQ6 扩大样本（可选，§11-Q6） | 酒店数 ≥ 150 时，单条 BDIA 的效应能否估计？ | 酒店 / 房源 | 预注册后再做。 |

**明确不做的结论：** 因果效应（横截面观察数据）；"入住率预测"（没有单酒店入住率数据，§4.3）；用 26–36 家酒店做条目级机器学习预测。

## §4 数据

### §4.1 已有（`data/raw/`，字典见 `docs/DATA.md`）
- 评论：35,177 行，2020-11-30 至 2023-11-30，52 个物业（含 19 个私人公寓 listing / 评论过少的物业），去重后有文字的 19,631 条。
- BDIA 编码：36 家 × 3 空间 × 29 条；分组 26 / 5 / 5（§1）。2 家（Royal Grove、Waikiki Monarch）三个空间编码完全相同，疑似只编一次后复制。
- 酒店层面：Booking 总分和 7 项子分、均价（2023 年 11 月抓取时点）。
- 问卷：只有结果表，没有逐人数据 → RQ 里不重新估计 SEM（§11-Q5）。

### §4.2 需要新收集
- **照片**（RQ1 必需）：36 家 × 3 空间，尽量与 2024 年评审看到的同类官方照片（大堂、Lounge、标准双床房含窗和卫生间）。放 `data/external/photos/`，不入库（版权），`manifest.csv` 记录来源。优先酒店官网，其次 Google Places API。
- 不再爬 Booking.com（服务条款）。旧评论数据继续用，作为 2020–2023 的横截面。

### §4.3 结果变量（实话实说）
- 单家酒店的入住率 / RevPAR 不公开（STR 收费；夏威夷旅游局 HTA 只有区域汇总）。
- 可用的代理：Booking 总分与子分；均价；每月评论数（≈ 入住量的粗代理，可从评论日期计算）。
- 如做 RQ6：Inside Airbnb 夏威夷数据（房源照片链接、评分、未来 365 天日历的不可订天数）——是房源不是酒店，结论要分开写。

## §5 方法与流水线（代码在 `src/biophilic/`，架构固定，见 `docs/DEV_PROMPT.md`）

### §5.1 读数与清洗（`io.py`、`clean.py`）
原始列名只在 `io.py` 出现；评论者名字读入即丢。占位句、"Nothing/None/N/A" 类回答、Booking 自动标题（"Exceptional" 等）置空；精确重复去掉；私人 listing 按名称规则标记；有文字评论 ≥ 50 条的酒店进入酒店层面分析。

### §5.2 评论文本
1. **规则基线**（`text/lexicon.py`，配置 `config/review_aspects.yaml`）：句子为单位；**极性来自 Booking 表单本身**（写在 "liked" 下 = 正面，"disliked" 下 = 负面），标题用 VADER；否定词窗口 3；物业名先屏蔽；高精度词（terms）和歧义词（ambiguous）分开，歧义词不进入任何模型；排除规则（exclude）专门对付 2024 年的误判。
2. **Claude 方面级情感抽取**（`text/llm_absa.py`）：每条评论一个请求，结构化 JSON 输出（方面、对应 BDIA 条目、空间、极性、是否明说、原文证据）；系统提示缓存；全量用 Message Batches API（半价、异步）；小样本同步模式带服务器端拒答回退（fallbacks）。方面 ID 与规则基线相同，方便对比。
3. **开源对照（可选）**：用户 fork 的 PyABSA（`pip install -e ".[absa]"`）可作为第三种方法在金标准上比较；不是主线。
4. **金标准**（`text/annotation.py`）：抽 400 条（一半是规则命中的，一半随机），人工逐方面标 "+ / − / 0"；建议两人各标一遍，先算标注者一致性。评估指标：检测的 precision / recall / F1，极性准确率。
5. 汇总（`text/aggregate.py`）：评论层面 0/1 指标；酒店层面 = 提及率（有分母）+ 收缩后的净情感 (pos−neg)/(pos+neg)。

### §5.3 BDIA 指数（`bdia.py`）
- `dimension_balanced`（默认）：每个空间先算 7 个维度各自的"有"的比例，再取平均；三个空间等权。
- `equal_items`：29 条的简单平均（论文 Ch3 原始定义）。
- 旧公式只用于审计（`config/legacy.yaml`），**不用于任何新结论**。
- 若以后要"学权重"：只能在训练酒店上学、在留出酒店上评估（嵌套交叉验证），并和等权指数比较；等权不输就用等权。
- 信度：每个维度的 KR-20；条目流行率（> 90% 或 < 10% 的条目区分力低，例如 B05 木质家具、C05 自然色家具）。

### §5.4 照片编码（`vision/vlm_coder.py`）
每个"酒店 × 空间"一次请求，最多 8 张照片；提示词来自 `config/bdia_items.yaml`（定义 + 看什么 + 不要混淆什么）；模型**看不到酒店名和分数**；每条输出 有/无、置信度、证据、对应照片编号；未返回的条目记为"未评估"，不猜。阈值 0.5 转 0/1。与专家编码比较用 `agreement.py`（κ 和 AC1）。
可选的定量补充（后续阶段）：Grounding DINO + SAM 2 分割，计算木材面积、绿植像素、窗墙比等连续变量。

### §5.5 统计模型（`models/`）
| 模块 | 内容 |
|---|---|
| `hotel_level.py` | 一行一家酒店；Spearman + bootstrap CI + 置换 p；BH-FDR；OLS（HC3）+ 留一法预测 R²；外部检验（26 → 10）；条目层面"论文做法 vs 正确做法"对照 |
| `review_level.py` | 评分 ~ 各方面正/负提及 + 旅客类型 + 年份 + 评论长度 + 酒店固定效应，SE 按酒店聚类 |
| `legacy_rf.py` | 复现论文随机森林；100 次随机行切分的测试 R² 分布；按酒店分组交叉验证；嵌套权重；置换零分布 |
| `stats.py` | 小样本推断工具 |

## §6 统计规范（每次分析都遵守）
1. **分析单位 = 结果变量变化的单位**：Booking 分是酒店层面的 → 一行一家酒店；评分是评论层面的 → 评论 + 酒店固定效应。绝不把同一个酒店分数复制到 3 行再当独立样本。
2. 任何"预测"都按酒店整家留出（GroupKFold / 留一酒店）；不做随机行切分。
3. 用来定义指数的东西不能来自结果变量；如果学权重，必须嵌套。
4. 主要检验在 §3 事先写死；其它都是探索性分析，标明"探索性"，并做 FDR。
5. 报效应量和 95% CI，不只报 p；n < 40 时用置换 p 值。
6. 固定随机种子（§9），`biophilic baseline` 可以完全复现 `results/`。

## §9 默认值（没被用户改过之前，后续会话直接用，不再问）
- Claude 模型 `claude-opus-5-5`；文本抽取 effort `low`，照片 `medium`；`config/pipeline.yaml → llm`。想省钱可改成 `claude-sonnet-5-5` 或 `claude-haiku-5-5`，但要先在金标准上重新验证 T7。
- 文本抽取先跑 100 条估算真实花费，再提交全量批处理。
- 酒店入选：有文字评论 ≥ 50 条且不是私人 listing。
- 默认指数 `dimension_balanced`，三个空间等权。
- bootstrap 2000 次，置换 5000 次，FDR 0.05，种子 20241102，GroupKFold 6 折。
- 金标准 400 条；照片每次请求最多 8 张；VLM 阈值 0.5。
- 规则基线只读英文评论（≈ 90%）；其它语言交给 Claude。
- 所有阈值、词表、提示词版本都在 `config/`，改配置不改代码。

## §10 局限与伦理
- 横截面、观察性数据；价格、品牌、翻新年份、位置只能部分控制 → 只说"关联"。
- 2023 年 11 月的分数和 2020–2023 的评论；照片若是 2026 年新拍的，酒店可能已翻新 → 照片来源和日期必须记录（manifest），优先找与 2023 年接近的存档照片。
- Booking 评分有选择偏差（愿意写评论的人）；照片是营销照片，系统性偏好看。
- 评论者名字不进任何派生文件；不从名字或文字推断任何受保护属性。
- 结论用于设计研究参考，不作为任何单家酒店的商业评级。
